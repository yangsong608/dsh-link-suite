## 0. 先定调：为什么是 MOSS，不是又一个玻璃拟态

移动端 AI 工具的主流视觉是「紫色渐变 + 毛玻璃 + 圆角卡片」。它的问题是：

1. **没有识别度**——把 logo 换掉就分不清是 Qoder、WorkBuddy 还是别的。
2. **不承载信息**——渐变的浓淡和产品的状态无关，装饰性越强，越容易被用户忽略。
3. **在手机上衰减快**——高斯模糊在低端 Android 上是最贵的 CSS 效果之一，而它带来的信息量为零。

`dsh-startup-moss` 给了一套完全相反的语言：**近黑、单色光、等宽字、终端框**。它便宜、锐利、有辨识度，而且**光本身就是状态**——红色是 550W（待机/守护），青绿是 MOSS（工作/思考）。这是一个能被状态驱动的视觉系统，而不是一层皮肤。

所以我们把 moss 的视觉 DNA 搬过来，但**不做启动动画的复刻**。原因是产品性质不同：moss 是"开机一次"的仪式，DSH Link 是"每天打开二十次"的工具。仪式感做一次是惊喜，做二十次是阻挠。

**判定规则**：任何动效如果第二次看还占时间，就必须变成可跳过或常驻微小化。

## 1. 视觉 DNA 五要素

这五条是从 moss 里抽出来的**可复用不变式**。新增任何页面、任何组件，先过这五条。

| # | 要素 | 规格 | 作用 |
|---|---|---|---|
| 1 | **暗场（dark field）** | 底不是纯黑，是带一点点冷/暖偏的近黑：MOSS `#050806`、550W `#0b0605` | 纯黑会让边框消失；偏色让"光"有落点 |
| 2 | **单色光（single hue）** | 全屏只允许一个强调色相，且只出现在「需要你看的地方」 | 颜色越少，一处亮色的注意力权重越高 |
| 3 | **扫描线（scanline）** | `repeating-linear-gradient` 每 1px 白 1.6% 透明，混色 `screen`，整体透明度 .38–.40 | 廉价（1 个伪元素）且立刻产生"屏幕"感 |
| 4 | **等宽字（mono）** | 数字、路径、代码、状态词一律 `ui-monospace`，小标题 `letter-spacing: .12em` + 大写 | 让"机器在说话"的部分看起来像机器在说 |
| 5 | **终端框（terminal frame）** | 1px 边框（强调色 42% 透明）+ 34px 顶栏 + 左上一个发光圆点 + 内部 70px 内发光 | 把"一块内容"变成"一台设备" |

> 关键细节：moss 的边框不是纯色，是 `rgba(强调色, .42)`，并且叠了三层阴影——外轮廓 1px、外部大范围晕、内部 70px 内发光。**这三层是"荧光屏"质感的全部来源**，省掉任何一层就变成普通卡片。见 `dsh-startup-moss/lib/splash.css:76-88`。

## 2. 双皮肤：MOSS 与 550W

沿用 moss 的语义，但赋予产品含义：

| 皮肤 | 语义 | 用在什么时候 |
|---|---|---|
| **MOSS**（冷青绿） | 连接、正常、可控 | 默认皮肤。设备在线、agent 空闲、一切正常 |
| **550W**（血橙红） | 待机、守护、告警 | ① 锁屏态 ② 危险操作确认（撤销设备、装插件、删工作区） |

**这不是两套更换的皮肤，是同一套皮肤的两个状态。** 用户可以在设置里锁定其中一种（有人就是喜欢红），但默认跟随语义自动切换：

```
锁屏 / 危险确认  →  550W（红）
其余一切        →  MOSS（青绿）
```

**有一件当初想做、后来否掉的事**：最初的设计是"有等待审批就整页变红"。原型跑出来后发现这是错的——设备页常年挂着"2 个任务在等你"，于是整页永远是红的，红色从此不再是信号，只是背景色。

现在等待用**元素级**表达：那张卡的描边变红、状态点变黄、以及"需要你"分组。整页变红只留给"要你亲手做一件危险的事"。

代价是失去了"扫一眼颜色就知道有没有事"的便利。补偿办法是把这件事交给**信息架构**——首页第一屏顶部就是"需要你"分组和待处理角标，比颜色更精确。

### 2.1 色彩 token（深色，主用）

### 2.2 浅色模式

必须给，因为手机系统白天会自动切。moss 的做法（`lib/theme.js`）是每套皮肤都备 light / dark 两半，我们沿用：

| Token | MOSS light | 550W light |
|---|---|---|
| `--bg` | `#F2F7F4` | `#F7F1E7` |
| `--s1` | `#FFFFFF` | `#FFFDF9` |
| `--bd` | `rgba(14,138,95,.16)` | `rgba(180,49,31,.16)` |
| `--t1` | `#0B1512` | `#1A0F0C` |
| `--t2` | `#4A5D55` | `#6B534C` |
| `--acc` | `#0E8A5F` | `#B4311F` |
| `--acc-glow` | `rgba(14,138,95,.20)` | `rgba(180,49,31,.20)` |

**浅色模式必须关掉三个东西**：扫描线、外发光、内发光。它们在亮底上只会变成脏污。这是最容易做错的地方——很多暗色设计一换浅色就崩，就是因为把"光"当成了"描边"。

## 3. 材质层：四个可叠加的便宜效果

全部是纯 CSS / Canvas 2D，**不引入任何图片资源**（moss 的 `assets/*.webp` 我们不用，因为 App 首包体积敏感）。

| 层 | 实现 | 成本 | 用在哪 |
|---|---|---|---|
| **veil**（扫描线） | `repeating-linear-gradient(0deg, rgba(255,255,255,.016) 0 1px, transparent 1px 4px)` + `mix-blend-mode:screen` + `opacity:.38` | 1 个伪元素，0 repaint | 全局最上层，`pointer-events:none` |
| **vignette**（暗角） | `radial-gradient(circle at 50% 45%, transparent 36%, rgba(0,0,0,.80) 100%)` | 同上，合并在 veil 里 | 全局 |
| **grain**（噪点） | 8×8 的 Canvas 生成一次 base64 PNG，`background-repeat` + `opacity:.03` | 一次性 1KB | 首屏、锁屏 |
| **glow**（呼吸光） | `radial-gradient(circle, var(--acc-glow), transparent 58%)` + `opacity` 过渡 1.2s | 合成层，需 `will-change:opacity` | 状态点、锁屏徽标、连接中 |

**性能红线**：`backdrop-filter` 全 App 禁用。需要用"毛玻璃"的地方，一律改成 `--s1` 半透明 + 1px 描边。理由：低端 Android 上一次 `backdrop-filter` 的合成开销约 4–8ms，而这个产品单屏可能有 20 个卡片。

## 4. 动效体系

### 4.1 时序基准

moss 的启动动画是四阶段：`boot → emblem → flip → final`（`lib/splash.js:55,523,531,546`）。我们只保留其**节奏**，不保留时长：

| 名称 | 时长 | 曲线 | 说明 |
|---|---|---|---|
| `--ease-out` | 180ms | `cubic-bezier(.22,1,.36,1)` | 90% 的交互反馈 |
| `--ease-in-out` | 260ms | `cubic-bezier(.4,0,.2,1)` | 抽屉、换页 |
| `--ease-snap` | 120ms | `cubic-bezier(.2,.9,.3,1)` | 按下、开关 |
| `--t-slow` | 620ms | `cubic-bezier(.4,0,.2,1)` | 启动、锁屏进出 |

**统一规则**：所有"用户操作引起"的动画 ≤ 260ms；所有"系统自己演"的动画 ≥ 500ms（否则看起来像故障）。

### 4.2 冷启动动画（1.4s，可跳过）

| 阶段 | 时长 | 画面 | 数据来源 |
|---|---|---|---|
| `boot` | 0–500ms | 终端框逐行打字：`DSH LINK v1.0` / `SCANNING 3 HOSTS` / `AUTH OK` | 真实设备数、上次选中的主机名 |
| `emblem` | 500–900ms | 徽标浮现 + 青绿呼吸光 | — |
| `flip` | 900–1200ms | 徽标 180° `rotateY` + `moss-glitch` 三帧抖动（18ms steps） | — |
| `final` | 1200–1400ms | 整体 `opacity → 0`，设备列表从下方 8px 上浮入场 | — |

**三个约束**：

1. 任意位置点击立即跳到 `final`（不是跳过整个流程，而是 fast-forward）。
2. 冷启动才播；热启动（App 从后台回前台）**只播 300ms 的值班动画**——MOSS 眨眼。
3. 首帧必须是**已经绘制好的静态徽标**，不能在动画里等网络。设备状态在动画期间并行加载。

`prefers-reduced-motion` 打开时：只保留 200ms 淡入，所有 glitch / 扫描线 / 呼吸停止。

### 4.3 常驻微动效（这是"炫酷"的主要来源）

真正让人觉得"高级"的不是启动动画，是**一直存在但不打扰**的东西：

| 元件 | 动效 | 周期 | 语义 |
|---|---|---|---|
| 在线状态点 | `box-shadow` 半径 6→10px 呼吸 | 2.4s | 活着 |
| 连接中 | 三格 `opacity` 阶梯波（不是转圈） | 1.2s | 在尝试 |
| 正在跑的会话 | 左侧 1px 竖条 `height` 上下扫 | 1.8s | 有输出 |
| 设备发现（配对页） | Canvas 雷达扫描：1 条 30° 扇形 + 3 个同心圆，扫到设备时该点 `glow` 脉冲 | 3s/圈 | 在找 |
| 打字中 | 方块光标 `steps(2)` 闪 | 1s | agent 在写 |
| 数字变化 | 等宽字 `font-variant-numeric: tabular-nums` + 数值 300ms 滚动 | 事件触发 | 数据在动 |
| 锁屏 | 扫描线 + 徽标呼吸 + 每 4s 一次极轻的 `moss-flicker`（透明度 40%→26%→48%） | — | 待机守护 |

**注意最后一个**：`moss-flicker` 的抖动幅度必须极小（3.9 秒里只有 3 帧变化，幅度 ±12% 透明度）。moss 原版就是这样（`@keyframes moss-flicker`：92% 和 100% 都是 .40，只有 93/95/97% 跳一下）。抖大了就是廉价故障风。

### 4.4 触感（haptic）映射

uni-app 用 `uni.vibrateShort({ type })`。**动效和触感必须成对设计**，否则动效是"看"，触感是"感觉"，两者错位会让人觉得卡。

| 事件 | 触感 | 动效 |
|---|---|---|
| 切 Tab | `light` | 下划线 180ms 滑动 |
| 发送指令 | `medium` | 气泡从输入框位置放大入场（`transform-origin` 对齐） |
| 批准 / 拒绝审批 | `heavy` | 卡片就地变结果态 + 一次 380ms 抖动（拒绝才抖） |
| 解锁成功 | `light` ×2（间隔 80ms） | 锁层 420ms 淡出 + 主页 8px 上浮 |
| 解锁失败 | `heavy` | 输入框 `moss-gate-shake`（`lib/gate.css:58-68` 的六段位移） |
| 设备离线 | 无 | 状态点由呼吸变为静态灰（不要弹 toast，不要抖） |
| 上传完成 | `light` | 进度条收尾 + 缩略图 1.02 倍回弹 |

**离线不震动**是一条产品决定：手机放在口袋里，震动代表"有事找你"，而设备离线不是事，是常态。

## 5. 关键组件视觉规格

### 5.1 终端卡（Terminal Card）——本产品的原子组件

所有"需要被当作一台机器看待"的内容都用它：设备卡、连接日志、插件安装输出、锁屏框。

```
┌──────────────────────────────────────┐  1px var(--bd-strong)
│ ●  DSH-LINK / HOST-01      12ms      │  34px 高，顶栏
├──────────────────────────────────────┤  1px var(--bd)
│                                      │
│  body                                │  内发光 70px
│                                      │
└──────────────────────────────────────┘
```

| 属性 | 值 |
|---|---|
| 圆角 | 10px（比卡片的 14px 更硬，像设备不像卡片） |
| 顶栏圆点 | 9×9，`var(--acc)`，`box-shadow: 0 0 10px var(--acc-glow)` |
| 顶栏字 | 11px / `letter-spacing:.12em` / `text-transform:uppercase` / `var(--t3)` |
| 背景 | `linear-gradient(180deg, s1 96%, bg 98%)`，带 1% 的方向性 |
| 发光 | 三层，见 §1 表下方说明 |

### 5.2 状态胶囊

| 状态 | 色 | 文案 | 形状 |
|---|---|---|---|
| 在线 | `--acc` | 在线 | 圆点 + 文字，底 `--acc-soft` |
| 连接中 | `--warn` | 连接中 | 三格波 |
| 需验证 | `--warn` | 需密码 | 锁图标 |
| 离线 | `--t3` | 离线 | 空心圆 |
| 已锁定 | `--acc`（550W 下） | 已锁定 | 锁图标 + 呼吸 |

**禁止**出现"检测中""同步中""加载中"这类第四种措辞。四个状态已经够多了（见 `03-产品设计.md` §7.1 的四层状态）。

### 5.3 雷达（配对页）

Canvas 2D，240×240，`devicePixelRatio` 缩放。

- 3 个同心圆，`rgba(acc,.18)`，半径 40/70/100
- 1 条 30° 扇形，从 0° 顺时针 3s/圈，`linear-gradient` 从 `rgba(acc,.22)` 到透明
- 扫到 host 点时：该点 40ms 内放大 1.6 倍再回弹 + 一次 `light` 触感
- 扫不到时**不做任何事**——不要"未发现设备"的红字，它只会让人焦虑

### 5.4 会话气泡与"活动行"

`04-UI设计.md` §5.3 已定结构。视觉上补三条：

- agent 的气泡**不加背景色**，只有 `--acc` 的左侧 2px 竖条（或完全没有，靠行宽区分）。moss 的终端里没有"气泡"，只有行。
- 工具调用渲染成**活动行**：`▸ Read` + 灰字路径 + 右侧耗时，等宽字 12px，hover/按下才显示完整参数。
- 思考中不用"..."，用**三行高度不等的占位条**扫过（1.05s），因为它暗示"内容正在生成"而不是"卡住了"。

### 5.5 执行过程时间线（trace）

这是需求 10 带来的新组件，也是本系统里**唯一一条"竖线"型布局**。三条视觉纪律：

1. **竖线不是装饰，是顺序**。左侧 20px 列里画 1px 竖线（`--bd`），把相邻步骤连起来；每行一个 12px 图标压在竖线上（用 `--s1` 做 2px 环把线断开）。这根线让"37 步"变成一条可读的时间，而不是 37 张卡片。
2. **图标形状必须能区分类型**，不能只换颜色——这和状态点是同一条无障碍要求（§8 第 4 条"色盲可辨"）：

   | kind | 图标 | 颜色 |
   |---|---|---|
   | `think` | 三点波浪 | `--t3` |
   | `text` | 竖条（段落） | `--t2` |
   | `tool` | 六边形 | `--acc` |
   | `file` | 文件折角 | `--acc`（改动量用 `--ok`/`--danger` 分别标 `+`/`−`） |
   | `term` | `>_` | 成功 `--t2`，失败 `--danger` |
   | `approval` | 三角形 | `--warn` |
   | `question` | 问号 | `--warn` |
   | `error` | 圆叉 | `--danger` |
   | `note` | 短横线 | `--t3` |

3. **`redacted` 条目要留出"这里本来有东西"的形状**。做法：内容区留一块 2px 虚线上边框 + 一行 11px `🔒 锁定中 · 内容不可见`。不要塌成 20px 的细条——那会被误认为"这一步没做什么"。

动效：新步骤入场用 120ms 的 `translateY(4px) → 0` + 淡入，**不做逐条排队动画**。一轮任务可能秒出 10 条，排队动画会让界面永远追不上数据。

### 5.6 消息队列条

- 收起态 36 高，背景 `--s2`，左侧 `3 QUEUED` 用等宽 10px + `letter-spacing: 1.2px`，和终端卡的顶栏同一套语气。
- 拖动时被拖起的那一行**放大到 1.02 并加 `--acc` 描边**，其余行让位（`transform: translateY`），不做位移动画以外的效果。
- 发送中的行右侧是一条 **1px 高的扫光**（复用 `.running-bar` 的 `scanDown`），不用进度环——队列条里没有空间给环，而且这里确实没有百分比。
- 队列空时**整条消失**，不留占位。空占位会让输入区上浮一截，用户每次进页面都觉得"位置变了"。

### 5.7 文件树与 diff

- **文件树不用卡片**。设备卡是"一台机器"，用终端框；文件是"一行东西"，直接列表 + `--bd` 分隔线。把文件做成卡片会让一屏只能放 5 个文件。
- 缩进 16px/级，最多 3 级后改用面包屑——超过 3 级缩进，手机上文件名就只剩 6 个字符。
- 目录图标用**折角方块**，文件图标用**带横线的方块**，靠轮廓区分而不是靠颜色。
- **diff 绝不使用整行背景色**。`+` 行左侧 2px `--ok`、`-` 行左侧 2px `--danger`，行底色始终 `--s1`。理由：满屏红绿底会让深色皮肤的对比度崩到不可读，而且红绿色盲用户完全依赖那 2px 边框和 `+`/`-` 符号。
- 代码行号列 32px，`--t3`，等宽，右侧 1px `--bd` 分隔；**行号不参与选中**（`user-select: none`），否则复制代码会带上行号。

## 6. uni-app 落地约束（必须遵守，否则风格会崩）

| 约束 | 说明 |
|---|---|
| **nvue 不用** | 全部走 Vue 3 + WebView 渲染。nvue 的原生渲染虽然快，但 `mix-blend-mode`、`radial-gradient`、`filter` 全不支持，一用就失去全部视觉语言。 |
| **rpx → px** | 视觉规格全部用 `px` 写在 `styles/tokens.scss` 里，布局用 `rpx`。混用会导致 750 设计稿在不同 DPR 下扫描线变粗。 |
| **Canvas 用 2d 上下文** | 不用 `uni.createCanvasContext`（旧 API 在高 DPR 下糊）。雷达、噪点、波形统一 `Canvas 2D`。 |
| **扫描线只挂一层** | 全局一个 `.dsh-veil` 固定层（`position:fixed; inset:0; z-index:9; pointer-events:none`），**不要**每个页面各挂一个。 |
| **动画只用 `transform` / `opacity`** | 唯一例外：进度条 `width`。`height`/`top` 动画在低端机上会掉帧。 |
| **单屏动画元件 ≤ 3** | 超过就砍。这是性能预算，不是美学建议。 |
| **低端机降级** | `uni.getSystemInfoSync().benchmarkLevel < 20` 时：关 grain、关 glow 呼吸（改静态）、扫描线 opacity 降到 .2。 |
| **深色为默认** | `manifest.json` 里 `app-plus.darkmode` + `pages.json` 的 `navigationBarBackgroundColor` 都跟 `--bg` 走，否则状态栏会白一条。 |

## 7. 禁忌清单

| 不要 | 因为 |
|---|---|
| 用 `backdrop-filter` 做毛玻璃 | 低端机 4–8ms/次，且和扫描线叠加会糊 |
| 用渐变按钮 | 单色光是本系统的基础，渐变会引入第二个色相 |
| 用 emoji 当图标 | 不同 Android 的 emoji 字体差异巨大，会破坏等宽对齐 |
| 让扫描线动起来 | 静态扫描线是"屏幕"，滚动扫描线是"复古游戏" |
| 在浅色模式保留发光 | 亮底上的发光 = 脏污 |
| 给每个卡片加阴影 | 终端框的三层阴影是稀缺资源，滥用就失去意义 |
| 让动效超过 620ms | 除冷启动外，超过 620ms 用户会以为卡了 |
| 用"AI 紫" | 与识别度预算冲突，且是本产品明确要避开的品类色 |

## 8. 验收方式

不是"看着像"。四条可测：

1. **灰度测试**：整屏转灰度后，仍能分辨 3 个信息层级（主文字 / 次文字 / 强调）。做不到说明层级只靠颜色，没靠明度和字号。
2. **60fps**：中端 Android（骁龙 6 系）上，设备列表滚动 + 3 个呼吸点 + 扫描线同时开启，`uni.getSystemInfo` 旁路用 `requestAnimationFrame` 采样，掉帧率 < 2%。
3. **首包**：`app` 构建后静态资源（不含 node_modules）< 400KB。视觉系统零图片是硬要求。
4. **色盲可辨**：MOSS 与 550W 的区分不依赖红绿——状态胶囊必须**同时**有形状差异（实心点 / 三格波 / 锁图标 / 空心圆）。红绿色盲占男性 8%，只靠色相区分等于对这部分用户失效。
