# DSH Link · UI 设计
> 注（2026-10-24）：文中 `app/...` 路径已迁出为独立工程 `moss-ai-app/...`（工作区根），阅读时按新位置理解。详见 [14-工程结构变更-app迁出.md](14-工程结构变更-app迁出.md)。

> 目标：**在 390px 宽的手机上，3 秒内看清"哪台机器在等我"，2 次点击完成批准。**
> 平板不是"放大的手机"，是"左列表 + 右详情"的工作台。

---

## 1. 设计原则

| # | 原则 | 具体做法 | 反例 |
|---|---|---|---|
| 1 | **状态先于内容** | 每屏顶部先回答"连上了吗 / 谁在等我" | 一进 App 就是聊天记录 |
| 2 | **一屏一件事** | 设备页只干"选机器"，会话页只干"选任务" | 设备、会话、设置混在一页 |
| 3 | **拇指可达** | 主操作固定底部 52px；顶部只放返回/标题 | 把"批准"放在右上角 |
| 4 | **压缩上下文** | Agent 活动默认一行摘要，点击展开 | 每条工具调用都铺满屏 |
| 5 | **危险要显眼** | 审批/撤销/装插件用红色系 + 不可跳过确认 | 用同一个蓝色按钮 |
| 6 | **不假装在线** | 离线就是离线，不用"加载中"掩盖 | 无限转圈 |
| 7 | **暗色优先** | 默认深色；浅色是等价映射，不是反转 | 暗色用纯黑 + 纯白字 |
| 8 | **光即状态** | 强调色由状态驱动：等你/告警=550W 红，其余=MOSS 青绿 | 用渐变装饰色，颜色与状态无关 |

> 原则 8 与完整视觉规格见 `05-视觉与动效-MOSS.md`。本文只保留布局与交互，颜色**不在本文定义**——单一来源，避免两处 token 漂移。

## 2. 设计语言（Design Tokens）

### 2.1 色彩

**色彩的全部定义在 `05-视觉与动效-MOSS.md` §2。** 本文只声明命名与语义，不重复色值。

两套皮肤（同一套 token 名，改值不改结构）：

| 皮肤 | 语义 | 什么时候自动切 |
|---|---|---|
| **MOSS** | 连接、正常、可控 | 默认 |
| **550W** | 待机、守护、告警 | 锁屏 / 危险确认 |

| Token | 用途 | 备注 |
|---|---|---|
| `--bg` | 页面底 | 近黑带偏色，不用纯黑 |
| `--s1` | 卡片 / 终端框底 | 原 `--surface-1` |
| `--s2` | 输入框 / 抽屉 / 气泡 | 原 `--surface-2` |
| `--s3` | 图标底 / 进度槽 / 选中 | 原 `--surface-3` |
| `--bd` / `--bd-strong` | 分割线 / 终端框边 | 1px，用透明度不用阴影 |
| `--t1` / `--t2` / `--t3` | 主 / 次 / 辅文本 | 原名 `--text-*` |
| `--acc` / `--acc-soft` / `--acc-glow` | 强调 / 强调底 / 外发光 | 原 `--accent` |
| `--ok` / `--warn` / `--danger` | 成功 / 等待 / 危险 | 与皮肤无关，固定值 |

语义色用法（不可混用）：

- **强调色（青绿或红）= 当前皮肤的"活着"**，只出现在需要你看的地方
- **黄 = 在等你**（waiting / 只读半锁）
- **绿（550W 下另取）= 通了 / 成了**
- **红（550W 下即强调色）= 会出事**——这也是为什么锁屏用 550W：**警戒色和强调色合流，视觉上最省**

> 颜色不是唯一信号：每个状态都配图标或形状（实心点 / 三格波 / 锁 / 空心圆），见 05 §8 的色盲可辨（第 4 条）。

> **迁移说明**：原方案用蓝紫 `#5B7CFA` 作主色。放弃它的理由写在 05 §0——蓝紫是 AI 工具品类的通用色，和"识别度"直接冲突，且它不承载状态信息。改名映射：`--surface-N → --sN`、`--border → --bd`、`--text-N → --tN`、`--accent → --acc`。

### 2.2 字体

| 角色 | 字号/行高 | 字重 | 用途 |
|---|---|---|---|
| Display | 28 / 34 | 600 | 页面大标题（平板空态） |
| Title | 20 / 28 | 600 | 导航标题 |
| Headline | 17 / 24 | 600 | 卡片主标题（设备名、会话名） |
| Body | 15 / 22 | 400 | 消息正文 |
| Caption | 13 / 18 | 400 | 次要信息、时间 |
| Micro | 11 / 14 | 500 | 徽标、状态点文字 |
| Mono | 13 / 20 | 400 | 路径、命令、diff |

- 中文用系统字体（PingFang / HarmonyOS Sans / Roboto），等宽用 `SF Mono` → `JetBrains Mono` fallback。
- **字号不随 rpx 缩放**：正文用 `px`，只有容器尺寸用 `rpx`。否则大屏上字会变成巨物。

### 2.3 尺寸

| Token | 值 | 说明 |
|---|---|---|
| 间距阶 | 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 | 4 的倍数 |
| 圆角 | 20（抽屉/大卡）/ 14（卡片）/ 10（控件）/ 999（胶囊） | |
| 触控最小 | 44 × 44 | 所有可点区域 |
| 主按钮高 | 52 | 底部 CTA |
| 列表行高 | 64（会话）/ 88（设备卡） | |
| 页面左右边距 | 16（手机）/ 24（平板） | |
| 分割线 | 1px `--border` | 不用阴影做层级（暗色下阴影不可见） |

### 2.4 动效

| 场景 | 时长/曲线 |
|---|---|
| 常规过渡 | 180ms `cubic-bezier(.2,.8,.2,1)` |
| 底部抽屉 | 260ms spring（damping .86） |
| 消息出现 | 120ms fade + 8px 上移 |
| 流式光标 | 1s 闪烁（`prefers-reduced-motion` 时禁用） |
| 进度环 | 线性，不弹跳 |
| 列表进入 | 30ms 逐项延迟（最多 6 项，之后不再延迟） |

## 3. 断点与布局

| 断点 | 判据 | 布局 |
|---|---|---|
| Phone 竖屏 | 宽 < 600 | 底部 3 Tab；对话全屏 push |
| **Phone 横屏** | 高 ≤ 520 | 单列；**只压竖向的壳**（导航 56→44、段切换 36→30、按钮 44→38） |
| Foldable / 大手机 | 宽 600 – 819 | 单列，内容限宽 760 居中 |
| Tablet 竖屏 | 宽 ≥ 820 **且高 ≥ 600** | **左侧栏 300 + 单列**，无底部 Tab |
| Tablet 横屏 / Desktop | 宽 ≥ 1100 **且高 ≥ 600** | 侧栏 344 + 对话 + **执行过程右栏 348** |

**断点必须同时判宽和高。** 手机横屏是 844×390，按宽度早过了平板门槛；
只按宽度切，会给一台 390 高的屏幕先拿走 300 宽，正文直接没法看。

```
Phone (<600)                 Tablet 横屏 (≥1100×600)
┌──────────────┐             ┌────────┬─────────────────────┐
│ 设备      ＋ │             │ 设备    │  会话标题     ⋯     │
│ ● MacBook    │             │ ● Mac  │ ─────────────────── │
│ ○ Studio     │             │  会话1 │  消息流…            │
│              │             │  会话2 │                     │
│ ┌──────────┐ │             │ ○ Win  │ ─────────────────── │
│ │ 等你 2 条 │ │             │  会话3 │  [输入区]           │
│ └──────────┘ │             └────────┴─────────────────────┘
│ 设备 会话 我的│              344px        自适应
└──────────────┘
```

uni-app 实现要点：
- 断点用 `uni.getSystemInfoSync()` 的 `windowWidth` / `windowHeight` + `onResize`（平板分屏、旋屏都会触发），
  算出 `phone | phone-landscape | fold | tablet | wide` 五档后挂到根节点的 class 上；
  **不要只靠 CSS 媒体查询**——H5 能用，App 的原生渲染层不认。
- 媒体查询可以作为 H5 的兜底，但两边的数字必须一致：`$bp-tablet: 820px` / `$bp-wide: 1100px`（见 `app/src/uni.scss`）。
- 平板双栏用 `flex`，左栏固定 `px`，右栏 `flex:1`；执行过程那一列固定 348，`min-height:0` 才滚得动。
- 安全区：`padding-bottom: calc(12px + env(safe-area-inset-bottom))`。

## 5. 关键页面规格

### 5.1 设备列表（首页）

```
┌─────────────────────────────────────┐
│ 设备                          ＋     │  导航 56
├─────────────────────────────────────┤
│ ⚠ 2 个任务在等你                     │  WaitingBanner（有才显示）
├─────────────────────────────────────┤
│ ● MacBook Pro                        │  DeviceCard 88
│   macOS 15 · 局域网 · 12ms      ⋯    │
│   3 个会话 · 1 个运行中               │
├─────────────────────────────────────┤
│ ◐ 公司工作站                          │
│   Windows 11 · 连接中…          ⋯    │
├─────────────────────────────────────┤
│ ○ 家里台式机                          │
│   离线 · 2 小时前                      │
├─────────────────────────────────────┤
│         ＋ 添加电脑                    │  次要按钮（空态时升为主按钮）
└─────────────────────────────────────┘
```

- 状态点：绿=在线，蓝闪=连接中，黄=需验证，灰=离线。
- 卡片副行固定三段：`系统 · 通道 · 延迟`，离线时改 `离线 · 最后活跃`。
- 长按 = 重命名 / 重新连接 / 查看诊断 / 移除。
- 下拉刷新 = 重测所有设备可达性（带 400ms 去抖，不闪"检测中"）。

```
│ 等你 2                               │  分组标题（13/600 大写间距）
│ ┌─────────────────────────────────┐ │
│ │ ⚠ 重构 auth 模块        刚刚     │ │  黄色左边条 3px
```

- 排序：等你 > 运行中 > 最近。
- "等你"分组永远在最上，且用左边条 + 主色文字，不用整块红（避免焦虑）。
- 左滑：归档 / 重命名。

### 5.3 对话页（核心）

```
┌─────────────────────────────────────┐
│ ‹ 重构 auth 模块            ⋯ ⚡    │  56
│   MacBook Pro · 局域网               │  ConnectionPill 内嵌副标题
├─────────────────────────────────────┤
│ 你                          14:02    │
│ ┌───────────────────────┐            │
│ │ 把 auth 改成 JWT，别动 DB │         │  用户气泡
│ └───────────────────────┘            │
│                                      │
│ 14:02                                │
│ 我先看一下现有的中间件…               │  助手正文（通栏）
│                                      │
│ ▸ ⚙ 运行 rg "middleware" src   3.2s  │  ActivityLine（折叠）
│ ▸ 📄 修改 src/auth/jwt.ts  +42 −8    │
│ ▸ ✅ 测试 12 passed                  │
│                                      │
│ 现在需要你确认：构建脚本要用生产密钥吗？│
│ ┌─────────────────────────────────┐ │
│ │ ⚠ 等待你批准                     │ │  ApprovalSheet 入口卡
│ │ npm run build                    │ │
│ │ 影响：会写 dist/ 并覆盖现有产物    │ │
│ │ ［拒绝］        ［批准］          │ │
│ └─────────────────────────────────┘ │
├─────────────────────────────────────┤
│ ＋  输入指令…                  ↑     │  输入区 56 + 安全区
└─────────────────────────────────────┘
```

要点：
- **助手消息不加气泡**（通栏），只有用户消息加气泡 → 视觉上"我在说话"和"它在干活"区分开。
- 工具调用一律折叠成一行 `ActivityLine`，点击展开 mono 详情；这直接对应 Qoder 的"活动压缩成一行"。
- 审批卡内联在消息流里，**同时**可点开底部抽屉看完整 diff/命令。
- 流式时输入区上方显示细进度条（2px），不转圈。

```
│                ────                  │  抓手

├─────────────────────────────────────┤
│ 命令                                 │
│ ┌─────────────────────────────────┐ │
│ │ $ npm run build                 │ │  mono, surface-2

│ └─────────────────────────────────┘ │
│ 会修改                               │
│  dist/index.js        +1.2 MB       │
```

规则：
- 风险分级映射颜色：读文件=中性，写文件=黄，执行命令=黄，删除/网络/密钥=红。

- 抽屉可下拉关闭（=不处理），但关闭后卡片仍在流里。
- 批准后原地变结果态（"你已批准 · 14:05"），不追加新消息。

```
│           → 添加手机                  │
│                                      │
│              手动输入地址             │
└─────────────────────────────────────┘
```

扫描成功后 → `FingerprintCompare`：大号 mono 6 位数字，两端对齐，下方"两端数字一致才继续"。

背景是 `MossRadar`：3 个同心圆 + 1 条 30° 扇形 3s/圈。**扫不到设备时不做任何提示**——不出现"未发现设备"的红字，它只会让人焦虑（视觉 §5.3）。

### 5.9 锁屏（覆盖层，需求 9）

**不是页面**。挂在根节点之上，任何页面任何深度都能出现，返回键关不掉。

```
┌────────────────────────────────────────┐
│ ●  DSH-LINK / HOST-01        LOCKED    │  顶栏，右侧 550W 红字
├────────────────────────────────────────┤
│                                        │
│            ▲ 徽标（呼吸 2.4s）          │  48×48 环形
│                                        │
│         SESSION SUSPENDED              │  13px / .18em / --t3
│                                        │
│  ┌──────────────────────────────────┐  │
│  │ ●●●●●●●○                      👁 │  │  dots 逐位点亮
│  └──────────────────────────────────┘  │
│                                        │
│  [      解  锁      ]  [ 请求远程确认 ] │
│                                        │
│  IDLE 10:24 · 3 个任务在后台继续        │  11px --t3，真实数据
└────────────────────────────────────────┘
```

| 元素 | 规格 | 说明 |
|---|---|---|
| 全屏底 | `--bg` + 径向渐变 + veil + grain | 皮肤**强制 550W**（不管用户选了什么） |
| 顶栏 | 34px，`--bd-strong` 1px | 同终端卡 |
| 徽标 | 48×48，`box-shadow` 6→14px 呼吸 | **不旋转**（旋转=在加载） |
| 密码框 | 8 个 dot，每位 60ms 缩放回弹 | 本屏唯一允许的炫技 |
| 主按钮 | 高 48，`--acc` 实底 | 拇指区 |
| 次按钮 | ghost，高 48 | 请求远程确认 |
| 底部信息 | `IDLE 10:24 · 3 个任务在后台继续` | 真实数据，回答"锁了任务还跑吗" |
| 失败 | 卡片 `moss-gate-shake` 380ms + 第 3 次起 `ATTEMPT 3 / 5` | 不弹 toast |
| 进入/退出 | 420ms 淡入淡出 | 沿用 moss 门禁时长 |

**手机端的锁屏态**（远程主机被锁时）：不是覆盖层，是设备卡上的一个状态胶囊 + 详情页里的一个按钮：

```
┌─────────────────────────────────┐
│ ● MacBook Pro        已锁定  🔒 │
│   12ms · 3 个会话 · 1 个运行中   │
│   [ 请求解锁 ]                   │
└─────────────────────────────────┘
```

**两者不要混**：PC 被锁时手机端仍然可用（能看会话列表的缓存、能请求解锁），所以手机上不出现全屏锁——只有"这台机器不能写"的提示条。

### 5.10 执行过程（trace 段，需求 10）

对话页顶部三段切换的第二段。**它不是日志查看器，是"它在干什么"的可视化**——所以每行先说人话，再说细节。

```
┌─────────────────────────────────────┐
│ 对话框 / 执行过程 / 产物             │  SegmentTabs，执行过程为当前
├─────────────────────────────────────┤
│ ✓ 读了 3 个文件              1.2s   │  trace 起点：批量动作合成一行
│ ● 思考                       2.4s   │  think，折叠（只显示摘要）
│ ✓ npm run build              18s    │  term，展开过，所以保留输出
│   └ 退出码 0 · 点击看完整输出        │
│ ✓ 改 src/auth/session.ts      +42 −8│  file，最重要：路径 + ±行数
│ ✓ 改 src/auth/cookie.ts       +7 −3 │
│ ⚠ 等待批准：rm -rf dist       [查看] │  approval，红色描边
│ 还有 37 步                    ▾     │  TraceGroup，默认折叠
└─────────────────────────────────────┘
```

规则：

| 项 | 规格 | 理由 |
|---|---|---|
| 左侧图标列 | 20px 宽，图标 12px，1px 竖线连接相邻行 | 让人一眼看出"这是一条时间线"，而不是一堆卡片 |
| `file` 行 | 路径 mono 12px，`+42 −8` 用 `--ok`/`--danger` 但**同时带符号** | 只靠颜色区分增减对 8% 的男性无效 |
| `term` 行 | 有 `exit !== 0` 时整行右边框 2px `--danger` | 失败的命令必须比成功的更显眼 |
| `redacted` 行 | 内容区显示 `🔒 锁定中 · 内容不可见`，不是空白 | 空白会被当成"加载失败" |
| 默认折叠 | 只展开 `file` / `approval` / `error` / 里程碑 `term` | 手机屏幕小，全展开等于刷屏 |
| 自动滚动 | 只在用户没手动上滑时跟随最新 | 手动上滑后跟着滚是移动端最烦的 bug |
| 空态 | `等待第一步…`（骨架点 3 个） | 不要空白页 |

**为什么不叫"日志"**：日志是给排错的人看的，trace 是给"想知道它有没有在乱来"的人看的。两者的默认展开策略、信息密度、语气都不一样。

### 5.11 消息队列（队列条，需求 10）

贴在输入区上方。**收起时只有 36px 高**，因为它不该抢对话的空间；有失败项时自动展开。

```
收起（有 3 条待发）
┌─────────────────────────────────────┐
│ ⠿ 3 QUEUED · 下一条「把测试也跑一遍」 ▴│  36 高，mono 计数
├─────────────────────────────────────┤
│ [ 继续输入… ]                  发送  │  输入区
└─────────────────────────────────────┘

展开
┌─────────────────────────────────────┐
│ 队列 3 条                        ▾  │
│ 1 ⠿ 把测试也跑一遍                  │  pending
│ 2 ⠿ 顺便把 README 更新一下          │  pending
│ 3 ⠿ 提交前帮我看下 diff             │  pending
│   ⚠ 上一条失败：上下文超限  [重发]   │  failed，红色行
└─────────────────────────────────────┘
```

- 拖动排序用长按（`⠿` 是把手），**不用左侧滑出删除**——两者在同一行会打架。
- `sending` 状态整行变 `--t3` 且把手消失（不可编辑，见 02 §3.5）。
- 发送中在行右侧显示 1px 进度扫条（`running-bar` 复用），不显示百分比（这个阶段没有百分比可言）。
- 上限 20 条，满了之后输入框右侧显示 `队列已满`，但**输入框仍可用**（用户可以选一条替换）。

**一条共享的骨架**：面包屑在上，列表在中，动作在右上。三层深度：工作区 → 目录 → 文件预览；仓库视图是并列入口，不是更深一层。

四条规则：

1. **二进制不做"尝试渲染"**：`fs.stat.binary` 为真时，直接显示"二进制文件 · 18 KB · [下载]"三个信息，不显示乱码。
2. **分页不用无限滚动**：文件内容用"继续加载"按钮。无限滚动在长文件上会让人永远滚不到底，而且拿不到"我在第几行"。
3. **diff 用边框不用底色**：`+` 行左侧 2px `--ok`，`-` 行左侧 2px `--danger`，行背景保持 `--s1`。满屏绿红底在深色皮肤下会毁掉对比度。
4. **仓库入口的可见性由 `caps.git` 决定**：为 0 时整个"仓库"入口不出现，而不是灰掉——灰掉的按钮只会让人反复点。

## 6. 平板 / 折叠屏

尺寸以 `08` §5 的断点表为准，本节只讲**为什么这样分**。

| 元素 | 平板竖屏（≥820×≥600） | 平板横屏（≥1100×≥600） | 折叠屏展开（600–819） |
|---|---|---|---|
| 导航 | 左侧栏 **300**（上：设备；下：会话树） | 左侧栏 **344** | 底部 3 Tab，**无侧栏** |
| 对话 | 单列，内容限宽 **760** 居中 | 左栏，可用宽 ≈502 | 单列，限宽 760 居中 |
| 执行过程 | **仍走三段切**（竖屏没有第二栏的空间） | **右栏 348 常驻**，与对话各自滚动 | 三段切 |
| 输入 | 底部固定，宽跟随内容列 | 底部固定，宽跟随对话列 | 底部固定 |
| 多任务 | 支持分屏（右栏最小 480） | 支持悬停态（上半预览/下半输入） | 分屏时退回三段切 |
| 空态 | 显示"选一个设备开始"，配大图标 | 同 | 同 |

平板不是"两列手机"，具体差别：
- 设备卡改为**紧凑行**（64 高），因为左栏窄。
- 会话树可展开工作区分组（手风琴）。
- 审批抽屉改为**居中模态**（560 宽），因为侧边抽屉在大屏上会跑太远。
- 键盘快捷键（外接键盘）：`⌘K` 切设备、`⌘Enter` 发送、`Esc` 关闭抽屉。
- **横竖屏旋转不丢状态**：正在看的会话、队列、滚动位置都保留；只重排布局，不重新拉数据。
  这条比"好看"重要——转一下就回到设备列表的 App，没人会转第二次。

### 6.1 折叠屏为什么不算平板

Galaxy Fold 这类展开后是 **673×841**（CSS 像素），N 代轴铰链机型在 700–800 之间。
按宽度它已经过了 600，但**没过 820**，所以落在"单列限宽 760"这一档。

曾经把它写成"同平板，但左栏 300px"——那是错的：673 减 300 只剩 373，
连 `middleware.ts` 的一行代码都显示不全（等宽 12px 下约 34 个字符）。
折叠屏展开的价值是"比手机多看到两行"，不是"比手机多一栏"。

## 7. 交互规范

| 场景 | 规范 |
|---|---|
| 触控反馈 | 所有可点元素按下态 `opacity .7` + 轻微缩放 `.98`，60ms |
| 震动 | 批准成功（轻）、审批到达（中）、危险确认（重）——可关 |
| 手势 | 右滑返回；对话内左滑无操作（避免误触）；抽屉下拉关闭 |
| 键盘 | `adjust-position`；输入区上移时消息流自动滚到底部；`confirm-type="send"` |
| 长按 | 消息：复制/引用；设备卡：菜单；会话：重命名/归档 |
| 下拉 | 设备页：重测连通；会话页：拉历史；对话页：加载更早 |
| 空态 | 必须有主行动按钮，不能只有插画 |
| 错误 | 一行原因 + 一行建议 + 一个按钮 |
| 超时 | 10s 未响应显示"仍在尝试…"，30s 显示重试（不自动断） |
| 危险确认 | 撤销设备/卸载插件/拒绝审批：需要明确点"确认"，不能滑动通过 |

## 8. 无障碍

- 对比度：正文 ≥ 4.5:1，大字 ≥ 3:1（已按 token 校验）。
- 动态字号：跟随系统，最大 1.3× 不破版（卡片高度自适应）。
- 读屏：每个状态点有 `accessibilityLabel`（"MacBook Pro，在线，局域网"）。
- 减少动效：`prefers-reduced-motion` 时去掉呼吸、光标闪烁、列表延迟。
- 色盲：状态同时用图标形状（●○◐⚠）区分。
- 触控：所有行高 ≥ 44，图标按钮加 8px 透明外扩。
