## 1. P1 设备页

### 1.1 数据流（修 D2）

```
onLoad
  └─ 若 state.devices 为空 → 显示空态
  └─ 若当前有 activeId → connectDevice → refreshAll

refreshAll（改造后）
  ① device.list           → 真实设备（已过滤撤销）
  ② 对每台设备调 device.info（或复用当前连接）拿 HostInfo
  ③ 合并策略：
     - 以 deviceId 为键
     - **旧的临时设备（tmp_*）在拿到真实设备后删除**
     - endpoint 按 deviceId 精确匹配；匹配不到的临时设备整条移除
  ④ 若 still 有 tmp_* 且 list 非空 → 说明配对未完成，提示重试
```

**关键修正**：v1 的实现是
```js
state.devices = devices.devices.map(d => ({ ...d, endpoint: endpoints.get(d.deviceId) }))
```
临时设备 id 是 `tmp_xxx`，真实 id 是 `dev_xxx`，`endpoints.get()` 必然 undefined，
而临时设备又没被删除 → **两条并存且都没 endpoint**。这就是 D1+D2。

**正确做法**：
```js
// 配对成功后，把临时设备替换成真实设备
const realIds = new Set(list.map(d => d.deviceId))
state.devices = [
  ...list.map(d => ({ ...d, endpoint: endpointFor(d), conn: 'online' })),
].filter(d => realIds.has(d.deviceId))
```

### 1.2 设备卡字段（修 D1）

| 字段 | 取值 | 拿不到时 |
|---|---|---|
| 名称 | `label` | `未命名设备` |
| 平台 | `platform` → 图标 | 通用 |
| 连接方式 | `endpoint.kind` | 不显示该段 |
| 延迟 | 客户端测（握手耗时） | 不显示 |
| 锁状态 | `host.lock` | 不显示 |
| 运行中会话 | 从 `session.list` 按 workspaceId 聚合 | 不显示 |
| 最近活跃 | `lastSeen` | 不显示 |

**元信息行拼接规则**（避免出现 `· ·`）：
```

line = parts.join(' · ')
```

## 2. P2 会话页

### 2.1 工作区分组（修 D4）

**数据结构**：

```ts
interface SessionGroup {
  workspaceId: string
  workspaceName: string
  pending: SessionRow[]   // waiting-approval / waiting-input
  running: SessionRow[]
  recent: SessionRow[]    // done / idle / error
  archived: SessionRow[]  // 折叠
  collapsed: boolean
}
```

**排序**：
1. 组间：有 pending 的组优先，其次按 `updatedAt` 倒序
2. 组内：pending → running → recent（各组内按 updatedAt 倒序）

**渲染**：

```
▾ 工作区 A                    3
  ⚠ 重构上传通道…        14:05
  ▶ 把 auth 换成…       进行中
  ○ 分析构建耗时          13:41
▸ 工作区 B                    1
▸ 已归档（12）          折叠
```

- 组标题 28px 高，可点折叠
- 折叠状态存 `uni.setStorageSync('dsh-link/collapsed/<wsId>')`
- 归档组默认收起，标题显示数量

### 2.2 过滤归档（修 D5）

`session.list` 返回的 `SessionSummary` 有 `blank`、`running`，但**没有 archived 标记**
（归档状态在 `workspaceController` 的 archive 记录里）。

**方案**：宿主侧新增 `session.list` 参数 `includeArchived`，默认 `false`。
宿主用 `workspaceController` 的归档记录过滤。

若宿主不支持（老版本），客户端按 `status === 'done' && 超过 30 天` 兜底分组——
**但要标注"可能不准确"**，不能假装精确。

### 2.3 会话行

照 `04-UI设计-v2.md` §2.2。

**长按** → 重命名 / 归档 / 取消归档。

## 3. P3 对话页（缺陷最集中）

### 3.1 顶栏（修 D7）

```
┌──────────────────────────────────┐
│ ‹  工作区A › 重构上传通道    ●运行中 │
└──────────────────────────────────┘
```

- 返回箭头 44×44
- 工作区名（可点 → 该工作区的会话列表）
- 会话标题（2 行截断）
- 状态点 + 文字（运行中/等待批准/已完成/出错）

**状态来源**：`session.follow` 的 snapshot 里 `header` 含状态；
后续 turn/start、turn/end 更新。

### 3.2 历史加载（修 D6，最关键）

**当前错误实现**：
```ts
// 只注册了事件监听，snapshot 被丢弃
await link.call('session.follow', { sessionId })
```

**正确流程**：

```
① 调 session.follow
   → 宿主回 evt，ch='sess:<id>', m='session.follow.snapshot'
   → 载荷含：{ header, cursor, records[], hasMore, projections }

② 渲染 records（这就是历史）
   注意每条形如 { type:'event', event:{ type, seq, time, data } }

③ 若 hasMore === true
   → link.call('session.page', {
       address: { kind: 'session', sessionId },
       throughSeq: cursor,
       // 注意层级：SessionHistoryRecord = SessionEventEntry = { type:'event', event }
       // seq 在 event 里，不是 record 上
       beforeSeq: records[0].event.seq - 1,
       maxMessages: 50,
     })
   → 把返回的 records 前插
   → 循环直到 hasMore === false 或用户停止

④ follow 持续推新事件 → 追加到列表尾部

⑤ 向上滚动到顶 → 再调 page 拉更早
```

**必须处理的三件事**：

| 情况 | 处理 |
|---|---|
| snapshot 为空 | 显示"这是一个新会话"，不显示骨架屏 |
| page 失败 | 显示"加载更早的消息失败 · 重试"，已加载的不丢 |
| 断线重连 | 用 `since: lastSeq` 续传，不重新拉全量 |

### 3.3 三段视图

| tab | 内容 |
|---|---|
| 对话 | user / assist / 工具行 / 审批卡 |
| 执行过程 | TraceItem 全量（含 think、file、term） |
| 产物 | `session.changes` 的文件列表 + 点开看 diff |

**手机上是切换，平板是并列**（照 `04-v2` §1.3）。

### 3.4 输入区（修"只有输入"）

```
┌──────────────────────────────────┐
│ 队列 2 条  ▾                      │  ← 有队列才显示
├──────────────────────────────────┤
│ [＋]  说点什么…           [ 发送 ] │
└──────────────────────────────────┘
```

- `＋`：附件（M2，现在点了提示"即将支持"）
- 发送：空时禁用

### 3.5 审批卡

照 `04-v2` §2.4。**补充**：

- 审批到达时 `haptic('heavy')` + 消息流滚到底
- 批准/拒绝后卡片原地变结果态（不打乱位置）
- 超时：卡片显示"已超时"并灰掉

## 4. 加载与错误态（每页都要）

| 页面 | 加载态 | 错误态 |
|---|---|---|
| 设备页 | 骨架卡 ×2 | 顶部条「设备状态可能不是最新的 · 重试」 |
| 会话页 | 骨架行 ×5 | 同上 + 保留已有列表 |
| 对话页 | 骨架消息 ×3 | 中部提示「历史加载失败 · 重试」 |
| 产物页 | 骨架行 ×3 | 中部提示 |

**原则**：错误不白屏，保留上一次成功的数据。
