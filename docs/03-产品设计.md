# DSH Link · 产品设计

---

## 1. 一句话定位

**把多台电脑上的 dsh 装进一个手机 App：看得见它在干什么，接得住它在等你，管得了它装了什么。**

不是远程桌面，不是 SSH 客户端，也不是云端 Agent。它是**你自己机器的遥控器**。

---

## 2. 为什么这个产品成立

### 2.1 用户问题（按痛感排序）

| # | 场景 | 现状 | 痛感 |
|---|---|---|---|
| 1 | 下班路上，任务在跑，想知道"到哪了" | 只能等回家；或开 TeamViewer 连桌面 | 高 |
| 2 | agent 弹审批，人不在电脑前，任务干等 | 任务卡住直到你回来 | **最高** |
| 3 | 在公司想让家里那台机器干活 | 得记 IP、配隧道、输带 token 的长 URL | 高 |
| 4 | 手机拍了照/收了文件，想让电脑上的 agent 处理 | 微信传自己 → 电脑下载 → 拖进去 | 中 |
| 5 | 三台机器各跑不同项目，想统一看 | 三个浏览器标签，各自登录 | 中 |
| 6 | 想给某台机器装个插件，但人不在 | 回家再说 | 低（但很爽） |

第 2 条是整个产品的立命之本。**远程看进度是"爽"，远程审批是"必须"。**

### 2.2 竞品对照

| | Qoder Mobile | WorkBuddy | dsh 现有插件 | **DSH Link** |
|---|---|---|---|---|
| 前提 | 官方云账号 | 官方云账号 | 自建 | **无账号，自托管** |
| 多机 | 同账号自动汇总 | 设备列表 + 在线点 | 多数只支持单机 | **设备列表 + 通道优先级** |
| 配对 | 登录即绑 | 登录即绑 | 扫码/密码不一 | **扫码 1 次，之后生物识别** |
| 通道 | 官方云 | 官方云 | LAN 或隧道 | **LAN / 自建中继 / Tailscale 任选** |
| 上传到工作区 | 附件 + 预览 | 拍照上传 | 基本没有 | **直写工作区（唯一）** |
| 装插件 | 不支持 | 改配置 | 需在电脑前 | **手机装卸 dsh 插件（唯一）** |
| 内网离线 | 不行 | 不行 | 部分可以 | **可以** |

**差异化只有一句话：他们卖"账号 + 云"，我们卖"你的机器 + 你的网"。**
代价是没有账号体系 → 配对必须自己做到 10 秒内完成，否则产品不成立。

## 3. 功能清单与优先级

P0 = MVP 必须有；P1 = 第一个正式版；P2 = 后续。

### 3.1 设备与连接

| 功能 | P | 说明 |
|---|:--:|---|
| 扫码配对 | P0 | 二维码含 hostId + 公钥指纹 + 全部 endpoint |
| 密码 / 生物识别 | P0 | 新设备要密码，之后 Face ID 解锁 |
| 设备列表（多 PC） | P0 | 名称、系统、在线状态、最近活跃、当前会话数 |
| 通道自动择优 | P0 | LAN → Tailscale → 中继，400ms 竞速 |
| 手动添加（IP/域名） | P1 | 扫码失败时的兜底 |
| 设备重命名 / 排序 / 移除 | P1 | 移除 = 本地删记录，可选"同时撤销主机授权" |
| 电脑端撤销设备 | P1 | 手机丢了的第一动作 |
| 局域网自动发现（mDNS） | P2 | 同 WiFi 免扫码 |

### 3.2 会话与对话

| 功能 | P | 说明 |
|---|:--:|---|
| 会话列表（按工作区分组） | P0 | 对齐 WorkBuddy 的"任务 + 工作空间"分组 |
| 实时流式对话 | P0 | 打字机 + 活动行 |
| 发指令 / 追加 / 中断 | P0 | 中断要二次确认（防误触） |
| 审批工具调用 | P0 | 底部抽屉，展示命令/文件/diff 摘要 |
| 回答 agent 提问 | P0 | 单选/多选/自由输入，多问分页 |
| **执行过程（trace）** | **P0** | 需求 10。一步一行：思考摘要 / 工具调用 / 文件改动 / 终端 / 报错。可折叠、可只看"关键步骤"、可点开看完整入参输出 |
| **消息发送队列** | **P0** | 需求 10。agent 忙时继续说话不报错，进队列；可看、可改、可删、可重排 |
| 新建会话 / 切换工作区 | P1 | |
| 会话重命名 / 归档 / 置顶 | P1 | |
| 历史消息分页回溯 | P1 | |
| 产物预览（图片/PDF/Markdown/HTML） | P1 | Qoder 的验收体验 |
| 本轮改动摘要 + patch | P2 | 参考 bridge 的 `/diff` |

**为什么执行过程和队列都是 P0**，尽管它们听起来像"高级功能"：

- **没有 trace，App 在 agent 跑长任务时是瞎的**。用户只看到"正在运行"四个字，既不知道卡在哪，也不知道它是不是在乱改文件。这时候唯一的动作是回电脑前看——而"不用回电脑前"正是这个产品的全部意义。
- **没有队列，用户被迫等**。一轮任务十分钟是常态，这期间想到的三件事要么憋着（然后忘），要么等（然后烦）。聊天软件二十年前就解决了这个问题（消息可以连着发），agent 客户端没有理由退回去。

两条产品约束：

1. **trace 默认折叠中间步骤**。默认只显示"关键步骤"（文件改动、审批、报错、里程碑），思考和闲聊类工具调用收进"还有 37 步"里。手机屏幕小，全展开等于刷屏，用户会直接关掉。
2. **队列不自动重试**。一条消息失败就停在那儿，显示原因。自动重试会把同一个错误刷三遍，用户还得判断"它到底发了几次"。详见 02 §3.5。

### 3.3 文件与仓库

| 功能 | P | 说明 |
|---|:--:|---|
| 上传到工作区 | P0 | 相册/文件/拍照；显示进度、可取消、断点续传 |
| 上传后直接交给 agent | P0 | "上传并让它处理"一条路径 |
| **工作区文件浏览** | **P0** | 需求 11。树形浏览 + 分页读；代码高亮、图片直显、Markdown 渲染 |
| **本轮产物（这轮改了哪些文件）** | **P0** | 需求 11。从 trace 的 file 事件聚合，带 ±行数；点进去看 diff |
| **git 状态与历史** | **P1** | 需求 11。分支、ahead/behind、暂存/未暂存/未跟踪分组、提交日志 |
| **diff 查看** | **P1** | 需求 11。统一 diff，按 hunk 折叠 |
| **GitHub 远程仓库浏览** | **P2** | 需求 11 的 M3 部分。需要 PC 侧配 token，默认关闭 |
| 下载 / 分享产物 | P1 | |
| 大文件后台传输 | P2 | 退到后台继续 |

**为什么把"浏览"提到 P0 而"上传"之外几乎不花成本**：这两件事的接口是同一个（`workspaceFiles`），只读面现成可用。而"看文件"恰好是手机最擅长的事——比在 PC 上翻目录还快，因为手机永远在手边。

**一条产品红线**：文件与仓库浏览**全部只读**，M2 不提供 commit / push / 删除文件。理由和上传那条一样——只读的价值是 90%，写入的风险是 100%。真要改代码，回到 PC 上改，那才是该在的地方。

### 3.6 锁定态（需求 9，锁的是 dsh，不是操作系统）

锁定是 **dsh 自身**的能力，不是操作系统的锁屏。对手机有直接产品含义：设备卡多了一个状态、首页多了一个"请求解锁"的动作、PC 上打开 dsh 只能看到锁屏界面。

| 功能 | P | 说明 |
|---|:--:|---|
| 手动锁屏（`⌘⇧L` / 菜单） | P0 | 一键，不等空闲 |
| 空闲自动锁（默认 10 分钟） | P0 | 可设 1/5/10/30/关 |
| 密码解锁 | P0 | 服务端 scrypt 校验，5 次/5 分钟限速 |
| 锁定态广播到手机 | P0 | 设备卡显示「已锁定」，不是「离线」 |
| 远程锁定（手机上把 PC 锁了） | P1 | 人在外面想起没锁，这是刚需 |
| 远程解锁请求（PC 弹窗确认） | P1 | 默认开；需要人在 PC 前点确认 |
| 生物识别解锁（Touch ID / Hello） | P1 | WebAuthn 平台认证器 |
| 只读半锁（8h 无操作） | P1 | 能看不能动，避免"看一眼也要输密码" |
| 解锁审计 | P1 | `lock / unlock.ok / unlock.fail` 进安全日志 |
| 恢复码 | P0 | 8 组四字短语，设置锁屏时强制展示一次 |

**四条产品规则**（比功能表重要）：

1. **锁的是 dsh，不是电脑**。用户在设置里看到的是「dsh 锁屏」，不是「锁屏」。我们不去调 OS 的锁屏 API：一个 dsh 插件申请系统级权限是权限放大，而且用户想锁系统的时候按 `Win+L` 比什么都快。这条界线要在文案里说清，否则用户会以为"锁了 dsh 就等于锁了电脑"。
2. **锁屏不暂停任务**。设置页必须写明「锁屏只锁操作，正在跑的任务会继续」。否则用户会以为锁了就白跑了，于是不敢锁。
3. **只读不要密码**。人在外面只想看进度，强制输密码的结果是用户把超时设成 8 小时。所以设「半锁」：看不用密码，动手要密码。
4. **文案必须诚实**。设置页锁屏开关下方那句话：「锁屏挡住的是人，不是进程。它防止别人看到你的会话或顺手操作，不能阻止本机上已经拿到权限的程序。」——这不是免责声明，是功能说明。

### 3.7 视觉体验（需求 8）

| 功能 | P | 说明 |
|---|:--:|---|
| 双皮肤（MOSS 青绿 / 550W 血橙红） | P0 | 默认跟随语义自动切：锁屏与危险确认用红，其余用青绿（等待审批**不**整页变红，否则红就成了背景色） |
| 扫描线 + 暗角 + 噪点 | P0 | 全局一层，零图片 |
| 终端框（设备卡 / 日志 / 锁屏） | P0 | 本产品的原子组件 |
| 冷启动动画（1.4s，可点跳过） | P1 | `boot → emblem → flip → final` 四阶段 |
| 常驻微动效（呼吸点 / 三格波 / 打字光标） | P0 | 这才是"高级感"的主要来源 |
| 配对雷达（Canvas） | P1 | 扫到设备才亮，扫不到不做任何提示 |
| 触感映射 | P1 | 与动效成对设计，见视觉文档 §4.4 |
| 用户锁定皮肤（不跟随语义） | P2 | 有人就是喜欢红 |

**为什么视觉是 P0 而不是"最后再美化"**：tokens 是一次性成本，早期建立后每个页面自动继承；放到最后做等于把所有页面重写一遍。这也是本次把它提到 M1 的原因（可行性 §6）。

### 3.8 明确不做（守边界）

- ❌ 屏幕串流 / 远程桌面
- ❌ 通用 SSH 终端（终端只作为 admin 的 P2 能力，默认关闭）
- ❌ 云端执行任务（我们没有云，也不打算有）
- ❌ 团队协作 / 会话分享（liveshare 是另一个产品）
- ❌ 自己实现模型接入（模型仍由 dsh 决定）
- ❌ **不做"锁屏即加密"**：不能宣传"锁屏后数据加密"。文件在工作区里是明文，锁屏只锁界面（06 §3 的 T4 说得更清楚）

## 4. MVP 边界

**一句话：能配对、能看、能批、能传、能锁。**

```
✅ 扫码配对 + 密码 + 设备列表（最多 5 台）
✅ 会话列表 + 对话流 + 发指令 + 中断
✅ 审批 + 回答问题
✅ 上传文件到工作区
✅ LAN 直连（应用层加密）
✅ 单机优先（多机列表可用但不同时连接）
✅ 视觉基线（双皮肤 tokens + 扫描线 + 终端框 + 呼吸点）
✅ dsh 锁定 L1/L2（界面锁 + 网关强制）+ 手动锁 + 空闲锁 + 恢复码
✅ 执行过程 trace（关键步骤 + 展开全部）+ 消息发送队列
✅ 工作区文件浏览 + 本轮产物列表（±行数）
❌ 中继、插件管理、通知、平板适配 → M2/M3
❌ 生物识别解锁、半锁、远程请求解锁 → M2
❌ git 状态/历史/diff、GitHub 远程仓库 → M2/M3
```

MVP 的验收标准（可测）：
1. 新手机从装 App 到看见会话，**≤ 60 秒**（含输入密码）。
2. 电脑上 agent 弹审批，手机**≤ 3 秒**收到并能在 2 次点击内批准。
3. 手机拍一张 5MB 照片上传到指定工作区，**≤ 4 秒**（同 WiFi），且 agent 能立刻读到。
4. 断开 WiFi 再恢复，会话**自动续上**，不丢消息、不重复。
5. **`⌘⇧L` 锁屏后，另一台设备发任何写操作都拿到 `lock/locked`；解锁后恢复。**
6. **锁屏状态下 App 首页设备卡显示「已锁定」而不是「离线」。**
7. **agent 跑任务时，执行过程页 3 秒内出现第一条步骤；改文件后 ±行数在 5 秒内出现在"本轮产物"里。**
8. **agent 忙时连发 3 条消息不报错，队列显示 3 条待发，顺序可拖拽调整；第一条发出后其余自动跟进。**

## 5. 信息架构

```
DSH Link
├─ 设备（默认首页）
│   ├─ 设备卡片列表（在线/连接中/需验证/离线 + 已锁定/只读）
│   ├─ 添加设备（扫码 / 手动）
│   └─ 设备详情
│       ├─ 概览（系统、版本、通道、延迟）
│       ├─ 会话（该机器全部会话）
│       ├─ 文件（工作区浏览）
│       ├─ 插件（admin）
│       └─ 设置（通道、唤醒、撤销、**锁定/请求解锁**）
├─ 会话（跨设备聚合，可选视图）
│   ├─ 进行中
│   ├─ 等待你（审批/提问）
│   └─ 最近完成
├─ 对话页（核心）
│   ├─ 顶部：会话标题 + 状态 + 切换「对话 / 执行过程 / 产物」三段
│   ├─ 对话段：消息流（气泡 + 活动行）+ 审批/提问卡片（内联）
│   ├─ 执行过程段：按步折叠的 trace（思考 / 工具 / 文件 / 终端 / 报错）
│   ├─ 产物段：本轮改动的文件列表（路径 + ±行数 → 点进 diff）
│   ├─ 队列条：有排队时贴在输入区上方（可展开、可拖动、可删）
│   └─ 输入区（文本、附件、语音 P2）
├─ 文件浏览（从设备详情或产物进入）
│   ├─ 目录树（面包屑 + 深度优先）
│   ├─ 文件预览（代码高亮 / 图片 / Markdown / 二进制提示）
│   └─ 仓库视图（分支 + 状态 + 提交历史 → 提交详情 → 单文件 diff）
└─ 我的
    ├─ 安全（设备、登录方式、审计日志、**锁屏策略**）
    ├─ 外观（**皮肤：跟随语义 / MOSS / 550W**）/ 通知 / 语言
    └─ 关于 / 诊断

**锁屏不是页面，是覆盖层。** 它挂在根节点之上，不属于任何 Tab——这样它在任何页面、任何深度都能出现，且返回键不会把它关掉。
```

导航模型：
- **手机**：底部 3 Tab（设备 / 会话 / 我的）+ 对话页全屏 push。
- **折叠屏展开（600–819 宽）**：仍是单列，内容限宽 760 居中；**不出侧栏**——
  这个宽度放一条 300 的侧栏，正文只剩 500 不到，比单列更难读。
- **平板竖屏（≥820 宽且 ≥600 高）**：左侧栏 300（设备 + 该设备的会话树）+ 单列，底部 Tab 撤掉（侧栏已经承担导航）。
- **平板横屏（≥1100 宽且 ≥600 高）**：左侧栏 344 + 对话 + **执行过程右栏 348**，两栏各自滚动。
  这是平板上唯一比手机强的场景：不用在对话和执行过程之间来回切段。
- **手机横屏（高 ≤ 520）**：不出侧栏，只压缩导航/段切换/输入框的竖向留白。

> 判档必须**同时看宽和高**。手机横屏是 844×390，宽度早已过 820 的门槛；
> 只按宽度切，会给一台本来就只有 390 高的屏幕先拿走 300 宽，正文直接没法看。
> 断点数字见 `04` §3、`08` §5，三处必须一致。

## 6. 核心流程

### 6.1 首次配对（目标 10 秒）

```
电脑：dsh 侧边栏 → DSH Link → 「添加手机」→ 出二维码（含 hostId/公钥/endpoints）
手机：首页「+」→ 扫码 → 显示 6 位指纹（两端一致）
     → 输入电脑上设置的访问密码（或电脑端点「允许」）
     → 命名这台手机（"我的 iPhone"）→ 完成，直接进入该设备会话列表
```

设计要点：
- 二维码**一次性、60 秒过期**，但可"重新生成"。
- 密码错误 3 次 → 二维码作废，回到电脑端点"允许"（防爆破，也防有人偷拍二维码）。
- 全程不要求用户理解 IP、端口、token。

### 6.2 日常（从锁屏到发出指令，3 步）

```
收到通知「任务需要你批准」→ 点通知直达对话 → 点批准
```

- 通知直达具体会话（深链），不落到首页。
- 冷启动优先恢复"上次设备 + 上次会话"。

### 6.3 上传文件

```
对话页「+」→ 拍照片/选文件 → 选择目标：
    ① 仅作为附件发给 agent（走官方附件通道）
    ② 上传到工作区（默认，落盘 + 可引用）
  → 显示进度环 → 完成后气泡里出现文件 chip
  → 可一键「让它处理这个文件」
```

产品决策：**默认 ②**。因为用户的心智是"文件要放到那台电脑上"，而不是"发给模型"。

### 6.4 远程装插件（P1，admin only）

```
设备详情 → 插件 → 搜索 "dsh-pocket"
  → 卡片显示：版本、描述、registry、是否 bundle
  → 「安装」→ 弹出风险确认（红色，需勾选）
  → 进度页（pnpm 日志流，可后台）→ 完成 → 「重启 dsh 生效」
```

### 6.5 手机丢了

```
另一台已配对设备 / 电脑端：
  设备列表 → 该手机 → 「撤销」
  → 该手机立即断开（bye: revoked），重连返回 401，必须重新配对
```

**这是安全模型必须闭环的一环**，也是 pocket 类方案做不到的（只能全员重置）。

### 6.6 锁屏与解锁（PC 侧）

```
触发（三种，权重相同）：
  ① ⌘⇧L / 菜单「锁定」
  ② 空闲 10 分钟（默认）
  ③ 手机端「锁定这台电脑」

锁定瞬间：
  LAN 里的 PC 界面 → 全屏 550W 终端锁屏（0.42s 淡入）
  正在跑的 agent   → 不受影响，继续跑
  所有在线设备      → 收到 lock.changed，写权限降到 viewer
  审计             → 写一条 {ev:"lock", reason}

解锁：
  ① 密码（服务端 scrypt 比对，5 次/5 分钟）
  ② Touch ID / Windows Hello（若已注册）
  ③ 恢复码（一次性）
  → 成功后：签发票据（12h）、广播 lock.changed、恢复角色、写审计
```

失败反馈：锁屏框抖动 380ms（`moss-gate-shake` 曲线），第 3 次起显示 `ATTEMPT 3 / 5`。**不弹 toast**——锁屏上弹 toast 等于把自己盖住。

### 6.7 手机请求解锁（人在外面，PC 锁着）

```
手机：设备卡 → 「已锁定」→ 「请求解锁」
  ↓
PC：右下角终端风小窗
    ┌─────────────────────────────┐
    │ ● HOST-01 / REQUEST         │
    │ iPhone 15 请求解锁           │
    │ [ 批准 ]  [ 拒绝 ]   30s 后自动拒绝 │
    └─────────────────────────────┘
  ↓ 批准
手机：倒计时环消失，设备卡变「在线」，可继续操作
```

**为什么不让手机直接输密码解锁**：手机可能是捡到的。人在 PC 前点一下"批准"是**物理在场证明**，比任何密码都强。默认关闭"手机输密码直接解锁"（配置项 `allowDeviceUnlock`）。

**超时自动拒绝**（30s）是必须的：否则你不在电脑前时，一个悬着的弹窗会一直等着被误点。

## 7. 状态与权限的产品表达

### 7.1 四层状态（用户只看前两层）

| 层 | 状态 | 呈现 |
|---|---|---|
| 设备 | 在线 / 连接中 / 需验证 / 离线 | 卡片左侧色点 + 一行文字 |
| 会话 | 运行中 / 等你 / 空闲 / 出错 | 会话行右侧徽标（"等你" 用主色高亮） |
| 轮次 | 思考中 / 运行命令 / 改文件 / 等审批 | 对话里一行活动摘要，可展开 |
| 通道 | LAN / 中继 / Tailscale | 设备详情里一行小字，不打扰 |

**只有"等你"能打断用户**（推送 + 角标）。其他状态一律安静。

### 7.2 权限的用户语言

不要出现 role 名。用行为描述：

| 内部 | 用户看到的 |
|---|---|
| viewer | "只能看" |
| operator | "可以对话和传文件" |
| approver | "可以替你批准操作" |
| admin | "完全控制（含装插件）" |

默认给 `approver`（因为审批是刚需，而装插件不是）。

## 8. 通知策略

| 事件 | 通知 | 说明 |
|---|---|---|
| 任务完成 | ✅ | 摘要 + 直达 |
| 等待审批 | ✅ 强提醒 | 高优先级，可锁屏操作（iOS 后续做 Live Activity） |
| 等待回答 | ✅ 强提醒 | |
| 任务出错/中断 | ✅ | |
| 设备离线 | ❌ | 不打扰，进 App 看 |
| 插件安装完成 | ✅ | 仅 admin |

技术降级链：`远程推送 → 本地通知（App 在后台 30s 内）→ 回前台补拉`。没有推送时，至少保证"打开 App 就能看到待办"。

## 9. 空状态与错误

| 场景 | 文案 | 动作 |
|---|---|---|
| 没有设备 | "还没有连接电脑。在电脑上打开 DSH Link，用这里的扫码添加。" | 扫码 / 手动添加 |
| 设备离线 | "这台电脑不在线。可能是休眠、断网，或 DSH 已退出。" | 重试 / 查看诊断 |
| 需验证 | "这台电脑要求重新验证。" | 输入密码 / 生物识别 |
| 版本不匹配 | "电脑上的插件版本较旧，部分功能不可用。" | 查看如何升级 |
| 上传失败 | "上传中断，已保留 3.2MB 进度。" | 继续 / 取消 |
| 审批已失效 | "这个请求已在电脑上处理。" | 返回会话 |
| 插件安装失败 | "安装失败：pnpm 在下载阶段超时。" | 查看日志 / 换 registry |

原则：**每条错误都要给出"下一步动作"**，不能只有一句"失败了"。

## 10. 指标

北极星：**每周通过手机完成的任务数**（不是 DAU，也不是消息数）。

| 层级 | 指标 | 目标（M3） |
|---|---|---|
| 获取 | 配对成功率 | ≥ 90% |
| 激活 | 首次配对到发出第一条指令 | ≤ 3 分钟（中位数） |
| 留存 | 次周仍使用远程的用户 | ≥ 45% |
| 核心 | 审批在手机上完成的占比 | ≥ 60% |
| 核心 | 通知到处理的中位时延 | ≤ 60s |
| 质量 | 断线重连成功率 | ≥ 99% |
| 质量 | 上传失败率 | ≤ 1% |
| 安全 | 未授权连接尝试拦截率 | 100% |

关键漏斗：`扫码 → 指纹确认 → 密码 → 命名 → 首条消息 → 首次审批`。每一档的流失都要能归因。

## 11. 版本路线

| 版本 | 主题 | 内容 | 成功判据 |
|---|---|---|---|
| **M1 / 0.1** | 能用 | 配对、设备列表、会话、对话、审批、上传、LAN、**视觉基线**、**锁屏 L1/L2 + 手动/空闲 + 恢复码**、**执行过程 trace + 消息队列**、**工作区文件浏览 + 本轮产物** | 自己每天用，一周不打开电脑端 |
| **M2 / 0.5** | 好用 | 中继、多机并行、断线恢复、平板分栏、通知、**生物识别解锁 + 半锁 + 远程请求解锁**、**git 状态/历史/diff** | 出差三天只带手机也能推进项目 |
| **M3 / 1.0** | 完整 | 设备撤销、审计、诊断、插件管理、产物预览、**冷启动动画 + 配对雷达 + 锁屏审计 UI**、**GitHub 远程仓库浏览** | 可以给陌生人用，不需要口头教学 |
| **M4 / 1.x** | 生态 | App 端插件、web-view 沙箱、dsh-mobile 扩展复用、扫码装插件、**App 插件自带视觉主题** | 第三方愿意写一个 App 插件 |

> 锁屏为什么从 M1 就开始：它和鉴权共用同一套会话、角色、审计代码（`02-技术方案.md` §4 与 §9.3），一起写是加法，分开写是重写。而视觉基线同理——放到 M3 等于把每个页面重做一遍。
>
> **执行过程与文件浏览为什么也在 M1**：它们决定了这个 App 到底是不是"能用的遥控器"。一个只能发消息、看不见过程、也看不见产出的客户端，用户用两次就会回到电脑前——因为**看不见就等于不放心**。而两者的成本都在"映射与分页"而不是"发明"，M1 做得起。
>
> **git 放 M2、GitHub 放 M3 的理由**：本地 git 只读无外部依赖，但它的价值要等"文件浏览"先立住（用户得先知道自己在看哪个文件，才会想看它的历史）；GitHub 远程浏览要 token、要处理限流与断网，把它塞进 M1 会让首发版本多一个"没配 token 就是空的"页面。

## 12. 三个产品判断（供讨论）

1. **不做账号**。做账号就意味着做云、做多租户、做合规。我们的护城河恰恰是"数据不出自己的网"。代价是配对必须极致简单——这是 M1 唯一的体验红线。
2. **审批优先于对话**。对话在手机上体验注定不如电脑（键盘、屏幕）。但审批只需要两次点击，手机反而更快。所以首页应该突出"等你处理"，而不是"聊天"。
3. **上传默认落到工作区**。这是与所有竞品的分水岭：他们把你手机的文件发给模型，我们把你手机的文件放进你的项目。前者是聊天，后者是干活。
