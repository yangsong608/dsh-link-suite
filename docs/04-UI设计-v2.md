## 1. 从竞品学到的三条布局原则

### 1.1 手机不是小屏桌面（Qoder Mobile）

Qoder Mobile 的官方描述里没有任何"编辑代码"的字样，全是：

> 查看 Agent 进度 · 处理关键审批 · 追加指令 · 预览并验收成果

**落到规范**：

| 原则 | 具体约束 |
|---|---|
| 只读为主 | 消息流、diff、产物都只读；可写的地方只有输入框和审批按钮 |
| 单指可达 | 所有主要动作在屏幕下半 40%（拇指区），顶部只放标题与状态 |
| 一屏一个决定 | 需要用户决策的卡片（审批、解锁）**独占一屏**，不与消息流混排 |

### 1.2 分组比时间更符合记忆（WorkBuddy）

WorkBuddy 侧边栏是「任务列表（**按文件夹分组**）」。

**落到规范**：

- 会话列表默认**按工作区分组**，每组可折叠
- 组内再按"等待你 / 进行中 / 最近"排序
- 工作区标题行高 28px，左侧 2px 竖条表示"这组有等待项"

### 1.3 结果与对话并列，而不是堆叠（WorkBuddy 四区布局）

WorkBuddy 的结果区在**右侧独立面板**，与对话区并列。

**落到规范**：

| 断点 | 布局 |
|---|---|
| < 600（手机竖） | 三段**切换**（对话/执行过程/产物），顶部 tab 切换 |
| 600–820（手机横/小平板） | 同上，但 tab 固定在顶栏 |
| ≥ 820（平板） | 左：会话列表；中：对话；右：产物（三栏，各自滚） |
| ≥ 1100（平板横） | 同上，右栏加宽到 360 |

**不做**：手机上把产物塞进对话流（会打断阅读，且产物通常比消息高得多）。

## 2. 组件规范

### 2.1 设备卡（P1）

**尺寸**：高 88px（含内边距），圆角 `--r-md`，左侧 3px 状态条。

```
┌─┬────────────────────────────────┐
│ │  MacBook Pro            ●12ms  │  ← 名称 + 延迟
│ │  darwin · 局域网 · 3 个会话     │  ← 元信息行
│ │  ● 运行中 1 个任务              │  ← 活动行（仅在有运行任务时）
└─┴────────────────────────────────┘
   状态条颜色见下表
```

**状态矩阵**（这是 v1 缺失的部分）：

| 连接 | 锁 | 状态条 | 卡片边框 | 顶部右侧 |
|---|---|---|---|---|
| online | 未锁 | `--acc`（绿） | `--bd` | 延迟 |
| online | 软锁 | `--warn`（黄） | `--bd` | 「只读」 |
| online | 硬锁 | `--danger`（红） | `--danger-bd` | 「已锁定」 |
| connecting | — | `--t3` 脉冲 | `--bd` | 「连接中」 |
| needs-auth | — | `--warn` | `--warn` 虚线 | 「需配对」 |
| offline | — | `--t3` 实心 | `--bd` | 「离线」 |
| 检测中（刚断线 <10s） | — | `--t3` 呼吸 | `--bd` | 「检测中」 |

**信息缺失时的降级**：字段拿不到就不显示该行，**不留空占位**
（空行会让卡片看起来像加载失败）。

**长按菜单**（`08` §3.1 原设计要求，v1 未实现）：

```
┌────────────────────────┐
│ 重命名                  │
│ 查看详情                │
│ 断开连接                │
│ ─────────────────────  │
│ 移除设备          (红)  │
└────────────────────────┘
```

- 长按 500ms 触发，`haptic('medium')`
- 「移除设备」二次确认：「移除后这台设备需要重新配对」

### 2.2 会话行（P2）

**高度**：64px（比设备卡矮，因为列表更长）。

```
┌──────────────────────────────┬──────┐
│ ⚠ 重构上传通道，加上断点续传    │ 14:05 │
│   需要你确认：覆盖 dist/ 3 个  │       │
└──────────────────────────────┴──────┘
  ↑ 状态图标（见下）              ↑ 时间/状态
```

**状态图标**：

| 状态 | 图标 | 颜色 |
|---|---|---|
| waiting-approval | ⚠ 实心三角 | `--warn` |
| waiting-input | ? 圆圈 | `--warn` |
| running | ● 脉冲点 | `--acc` |
| done | ○ 空心圈 | `--t3` |
| error | ✕ | `--danger` |
| idle | ○ | `--t3` |

**分组标题行**：

```
▾ 工作区 A                    3
  ↑ 折叠箭头  ↑ 名称（14px）   ↑ 计数（mono）
```

- 有等待项的组：名称前加 2px `--warn` 竖条
- 折叠状态记忆在本地（下次进入保持）

### 2.3 消息流（P3）

**四种条目**：

| 类型 | 呈现 | 依据 |
|---|---|---|
| 用户消息 | 左侧 2px 竖条 + 正常字号 | v1 已定（无气泡） |
| agent 文本 | 同上，颜色略暗 | 同上 |
| 工具调用 | **一行**：`▸ Read upload.ts  42ms`，可点开 | Qoder「看进度」的最小粒度 |
| 审批卡 | 独占一屏宽度，高亮边框 | WorkBuddy「先预览」 |

**工具调用为什么折叠成一行**：Qoder Mobile 的核心是"看进度"，不是"看日志"。
一行足够判断"它在读文件还是在跑测试"，点开才需要细节。

### 2.4 审批卡（最关键的组件）

```
┌──────────────────────────────────┐
│ ⚠ 需要你的批准                     │  ← --warn 标题
├──────────────────────────────────┤
│ Bash                             │  ← 工具名（mono）
│ npm run build                    │  ← 命令/参数摘要
│                                  │
│ 影响：写入 dist/ 下 3 个文件       │  ← 影响范围（WorkBuddy「先预览」）
│       +1.2 MB                    │
├──────────────────────────────────┤
│  [ 拒绝 ]        [ 允许一次 ]     │  ← 拒绝在左（防误触）
└──────────────────────────────────┘
```

**规范要点**：

| 项 | 值 | 理由 |
|---|---|---|
| 宽度 | 屏宽 - 32px | 独占视觉重量 |
| 边框 | 1px `--warn` / `--danger` | 按风险等级 |
| 按钮顺序 | **拒绝在左，允许在右** | 右手拇指更容易点到右侧，但"允许"是危险动作——所以右侧反而不是默认位；实际是让"拒绝"成为更易点的那个 |
| 按钮高度 | 44px | 触控下限 |
| 超时 | 显示倒计时环 | dsh 侧默认 60s |
| 震动 | `haptic('heavy')` | 必须让人注意到 |

### 2.5 输入区（P3）

```
┌──────────────────────────────────┐
│ 队列 2 条 ▾                       │  ← 仅在有队列时出现
├──────────────────────────────────┤
│ [＋]  说点什么…           [ 发送 ] │
└──────────────────────────────────┘
```

| 元素 | 规范 |
|---|---|
| 高度 | 52px（输入框 44 + 上下 4） |
| 发送按钮 | 空输入时 `opacity .38` + `pointer-events: none` |
| 队列条 | 高 28px，点击展开队列列表 |
| 安全区 | 底部 `--safe-bottom-real` |

## 3. 反馈规范（远程场景特有）

### 3.1 三档反馈

| 场景 | 反馈 | 时长 |
|---|---|---|
| 本地操作成功（切 tab、展开） | 触感 + 视觉过渡 | 即时 |
| 远程操作成功（发送、批准） | 触感 + 轻 toast | 1.5s |
| 远程操作失败 | 触感（重）+ 可重试的提示条 | 直到用户处理 |

**关键**：远程操作的"成功"必须是**宿主确认后**才算成功。
本地乐观更新会让人以为发出去的消息其实丢了（WorkBuddy 的云端任务同理）。

### 3.2 连接状态反馈

| 状态 | UI | 位置 |
|---|---|---|
| 连接中 | 顶部 24px 细条，`--acc` 流动 | 页面顶端 |
| 已断开 | 顶部 32px 条，「连接已断开 · 重试」 | 页面顶端 |
| 重连中 | 同"已断开"，附带倒计时 | 页面顶端 |
| 重连成功 | 条消失 + 轻触感 | — |

**不做**：全屏遮罩。断线时用户仍应能翻看已加载的内容。

### 3.3 空态清单（每个都要写文案）

| 页面 | 空态文案 |
|---|---|
| 设备页 | `还没有配对的电脑` / `在电脑上打开 DSH → 设置 → MOSS Link → 生成配对码` |
| 会话页（无设备） | `先配对一台电脑` |
| 会话页（有设备无会话） | `这台电脑还没有会话` / `在电脑上开一个吧` |
| 对话页（无历史） | 不显示空态——历史加载中显示骨架屏 |
| 产物页 | `这一轮还没有产物` |

## 4. 排版与间距（沿用 v1，补例外）

v1 已定：字号阶梯 21/15/14/12.5/11.5/10.5，间距 4 的倍数，圆角 `--r-md`。

**v2 新增例外**：

| 场景 | 例外 | 理由 |
|---|---|---|
| 会话标题 | 允许 2 行，超出省略 | 标题常含关键信息（文件名） |
| 工具名 | mono 12px | 等宽更易扫读 |
| 倒计时 | mono，`font-variant-numeric: tabular-nums` | 数字跳动时宽度不变 |
| 二维码 | 整数像素对齐 | 非整数缩放会让模块模糊 |

## 5. 无障碍与容错

| 项 | 规范 |
|---|---|
| 触控目标 | 最小 44×44 |
| 对比度 | 正文 ≥ 4.5:1；状态色不单独承载信息（配图标或文字） |
| 动效 | `prefers-reduced-motion` 下关闭脉冲与扫描线 |
| 长按 | 必须有替代入口（菜单按钮），因为长按对部分用户不可达 |
| 错误 | 每个错误都有"下一步做什么"，不只是"失败了" |

## 6. 与 v1 的差异

| 项 | v1 | v2 |
|---|---|---|
| 平板布局 | 提了三档断点 | 明确到"手机三段切换 / 平板三栏" |
| 设备卡 | 有视觉描述 | 补 7 种状态矩阵与降级规则 |
| 审批卡 | 有尺寸 | 补按钮顺序、影响范围、超时环 |
| 反馈 | 只有触感 | 三档反馈 + 远程操作必须宿主确认 |
| 空态 | 部分 | 每页都有文案 |
| 长按菜单 | 原设计要求 | 明确菜单项与二次确认 |
